# notion-ops

노션 작업마다 [`ntn` CLI](https://developers.notion.com/cli)(명령줄 도구)와 MCP(외부 도구 연결 방식) 노션 커넥터 중 덜 드는 쪽을 고르고, 실제 커맨드까지 잡아 주는 스킬입니다.

[SKILL.md](SKILL.md) · [설치](#설치)

## 구성

notion-ops는 노션 요청을 받으면 다섯 가지를 차례로 정합니다.

1. **위치를 아는 작업** — 등록·조회·수정·쿼리는 CLI로 보냅니다.
2. **워크스페이스 전체 검색** — 시맨틱 검색(뜻으로 찾는 검색)은 MCP로 보냅니다. 워크스페이스 플랜에 AI 검색이 켜져 있을 때만입니다.
3. **외부 소스 검색** — Slack·Drive 같은 연결된 외부 소스까지 찾아야 하면 MCP로 보냅니다.
4. **커맨드** — 고른 쪽의 실제 커맨드를 잡아 줍니다. 커맨드 레퍼런스와 `ntn api`의 인라인 입력 문법(`=` / `:=` / `==`)이 들어 있습니다.
5. **함정 피하기** — 실제 워크스페이스에서 커맨드를 전부 돌려 보며 기록한 함정을 피합니다.

## 상황별 사용

### 로컬에서 쓴 문서를 노션에 올릴 때

로컬에 있는 회의록이나 기획서를 정해진 노션 페이지 아래에 등록하는 상황입니다.

사용할 도구: CLI (`ntn pages create`)

### 이미 올린 페이지를 고칠 때

위치를 아는 노션 페이지의 본문이나 프로퍼티를 바꾸는 상황입니다.

사용할 도구: CLI (`ntn pages update`, `ntn api v1/pages/<id> -X PATCH`)

### 노션 DB에서 조건에 맞는 행을 뽑을 때

데이터베이스에서 상태나 날짜로 걸러 목록을 보는 상황입니다.

사용할 도구: CLI (`ntn datasources query`)

### 어디 있는지 모르는 문서를 찾을 때

제목이나 위치를 모르는 문서를 워크스페이스 전체에서 찾는 상황입니다. 세션당 한 번 AI 검색이 켜져 있는지 확인하고, 꺼져 있으면 CLI로 찾습니다.

사용할 도구: MCP `notion-search`(AI 검색이 켜져 있을 때) 또는 CLI `ntn api v1/search`

### 슬랙이나 드라이브까지 함께 찾아야 할 때

노션에 연결된 외부 소스까지 뒤져야 하는 상황입니다.

사용할 도구: MCP `notion-search`

## 가이드라인

### 위치를 아는 작업은 CLI로 보냅니다

CLI는 bash가 디스크의 파일을 API로 바로 넘깁니다. 콘텐츠가 모델의 출력 토큰을 한 글자도 거치지 않습니다. MCP는 모델이 문서 전체를 `content` 파라미터에 다시 입력해야 합니다. 차이는 우연이 아니라 이 구조에서 나옵니다.

### 문서가 많아도 MCP로 바꾸지 않습니다

CLI와 MCP의 토큰 배율은 문서 양이 늘어도 줄지 않습니다. "파일이 많으니까 MCP도 비슷해지겠지"는 틀린 판단입니다. 측정값은 [근거](#근거)에 있습니다.

### 검색은 AI 검색을 확인한 뒤에만 MCP로 보냅니다

MCP의 검색 우위는 워크스페이스에 AI 검색이 켜져 있을 때만 성립합니다. 스킬은 이를 가정하지 않고 세션당 한 번 직접 확인합니다. 반면 Slack·Drive 같은 외부 소스 검색은 플랜과 무관합니다. `ntn`은 노션 공개 API만 감싸기 때문에 구조적으로 MCP만 할 수 있습니다.

### `ntn api`의 입력 문법을 먼저 맞춥니다

`=`는 본문 필드, `:=`는 JSON 값, `==`는 쿼리 파라미터입니다. 이 문법은 400 에러의 가장 흔한 원인입니다.

| 지양 | 권장 |
|---|---|
| MCP `notion-create-pages`를 쓴다 | `ntn` CLI를 쓴다 |
| 모델이 본문을 `content`에 직접 입력한다 | bash가 디스크에서 읽어 API로 넘긴다 |
| 도구 호출 안에 문서 전문을 넣는다 | `ntn pages create --parent page:<id> < 회의록.md` |
| 모델이 결과를 다시 읽어 확인한다 | `diff <(ntn pages get <id>) 회의록.md`로 확인한다 |

표는 "회의록.md를 팀 위키 페이지 아래에 올려 줘"라는 가상의 예입니다.

## notion-ops vs MCP 직접 사용

| | notion-ops (CLI 기본) | MCP 노션 커넥터 |
|---|---|---|
| 맡는 작업 | 위치를 아는 등록·조회·수정·쿼리 | 워크스페이스 전체 시맨틱 검색, 외부 소스 검색 |
| 콘텐츠 전달 | bash가 파일을 API로 넘긴다 | 모델이 본문을 직접 입력한다 |
| 조건 | 없음 | 시맨틱 검색은 AI 검색이 켜져 있을 때만 |
| 토큰 | 약 1.87~1.97배 적다 | 기준 |

에이전트는 이미 연결된 MCP 커넥터부터 잡는 경향이 있습니다. notion-ops는 기본을 CLI로 두고, CLI가 할 수 없는 검색만 MCP로 넘깁니다.

## 근거

## 검증

`ntn 0.16.0`, macOS, 실제 워크스페이스에서 확인했습니다.

- **방법** — `SKILL.md`의 모든 커맨드를 문서에서 옮겨 적지 않고 직접 실행했습니다.
- **찾은 것** — 작성 시점 공식 문서가 틀린 곳 두 군데를 찾았습니다.
  - 페이지 수정 서브커맨드는 `ntn pages update`입니다. `ntn pages edit`은 없습니다.
  - 프로퍼티 스키마는 database가 아니라 data source에 있습니다. `ntn api v1/databases/<data-source-id>`는 400이 납니다. `ntn datasources resolve <database-id>`로 먼저 변환합니다.
- **확인하지 못한 것** — `--parent`의 세 형식 중 `database:<id>`는 실행으로 확인하지 못했습니다. `page:`와 `data-source:`만 확인했습니다.

## 설치

CLI를 설치하고 인증합니다.

```bash
curl -fsSL https://ntn.dev | bash
ntn login
ntn whoami      # 인증 상태와 어느 워크스페이스인지 한 줄로 확인
```

헤드리스·CI 환경이면 `NOTION_API_TOKEN`을 씁니다. OS 키체인을 못 쓰면 `NOTION_KEYRING=0`을 설정합니다. 워크스페이스가 여러 개면 `NOTION_WORKSPACE_ID`를 설정합니다.

스킬을 배치합니다.

```bash
mkdir -p ~/.claude/skills/notion-ops && cp SKILL.md ~/.claude/skills/notion-ops/
```

한 프로젝트에만 쓰려면 저장소 안의 `.claude/skills/notion-ops/`에 둡니다. 등록 절차는 없고, 다음 세션부터 Claude가 알아서 꺼내 씁니다.

## 범위와 한계

- 라우팅과 실행을 다룹니다. 노션 Workers는 다루지 않습니다.
- MCP 노션 커넥터는 작업에 정말 필요할 때만 있다고 가정합니다. 없으면 검색과 외부 소스 항목만 빠지고 나머지는 그대로 동작합니다.
- 토큰 수치는 워크스페이스 하나와 토크나이저 하나에서 나왔습니다. 결과의 방향이 핵심이고, 정확한 배율은 추정치로 봅니다.
