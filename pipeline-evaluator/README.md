# pipeline-evaluator

리뷰에서 생성한 구매 고민 질문이 매핑된 리뷰와 맞는지 LLM(대규모 언어 모델)으로 채점하는 스킬입니다.

[SKILL.md](SKILL.md) · [설치](#설치) · 함께 쓰는 스킬: [writer-checker-loop](../writer-checker-loop/)

## 구성

pipeline-evaluator는 리뷰 분석 파이프라인의 Step 4 결과물(`concerns.json`)을 다섯 단계로 채점합니다.

1. **리뷰 원문 모으기** — `scripts/evaluate.py`가 `reviewIds`로 원본 리뷰를 찾습니다. 원문을 찾지 못한 질문은 건너뜁니다.
2. **채점 요청** — 질문 하나당 API(외부 모델 호출)를 한 번 부릅니다.
3. **세 지표 계산** — 아래 표의 구체성, 적합도, 커버리지를 냅니다.
4. **커버리지 신호** — 40% 미만이면 위험(질문이 지엽적), 90% 초과면 경고(변별력 없음)로 표시합니다.
5. **결과 출력** — 콘솔 요약과 JSON 리포트로 냅니다.

| 지표 | 단위 | 내용 |
|---|---|---|
| 구체성 (Specificity) | 질문당 0~2점 | 상황·조건 같은 디테일이 질문에 들어 있는가 |
| 적합도 (Relevance) | 리뷰당 1~5점 | 그 리뷰가 질문에 대한 답이 되는가 |
| 커버리지 (Coverage) | % | 적합도 3점 이상 리뷰 수 / 평가한 리뷰 수 |

## 상황별 사용

### Step 4 결과물이 막 나왔을 때

생성된 구매 고민 질문이 매핑된 리뷰와 맞는지 처음 확인하는 상황입니다.

볼 지표: 구체성, 적합도, 커버리지 전체

### 질문이 너무 좁아 보일 때

질문에 답하는 리뷰가 거의 없어 과적합이 의심되는 상황입니다.

볼 지표: 커버리지 40% 미만(위험)

### 질문이 너무 넓어 보일 때

아무 리뷰나 다 맞아 질문이 변별력을 잃은 것 같은 상황입니다.

볼 지표: 커버리지 90% 초과(경고), 구체성 점수

### 파이프라인을 고친 뒤

변경 전후로 질문 품질이 나아졌는지 비교하는 상황입니다.

볼 지표: 같은 모델·같은 `--max-reviews`로 돌린 전후 리포트

### 평가할 대상이 파이프라인 출력이 아닐 때

이력서나 포트폴리오 카피처럼 문서를 쓰고 검사해야 하는 상황입니다.

함께 쓰는 스킬: [writer-checker-loop](../writer-checker-loop/)

## 가이드라인

### 질문은 너무 좁아도, 너무 넓어도 실패입니다

그럴듯한 질문이라도 매핑된 리뷰가 실제로 답하는지는 따로 봐야 압니다. 질문이 너무 좁으면 답하는 리뷰가 거의 없습니다. 너무 넓으면 아무 리뷰나 다 맞습니다. 커버리지는 이 둘을 숫자로 드러냅니다.

### 커버리지 경계값은 신호로만 읽습니다

40%와 90%는 스크립트에 고정된 기준입니다. 별도 검증을 거친 값은 아닙니다. 스크립트는 40% 이상 90% 이하를 모두 적정으로 표시합니다.

### 전후 비교는 같은 설정으로 돌립니다

LLM 판정이라 실행마다 점수가 조금씩 다를 수 있습니다. 모델과 `--max-reviews`를 같게 두고 비교합니다.

### API 키는 저장소에 커밋하지 않습니다

키는 환경 변수나 `.env` 파일로 넘깁니다. `.env`는 저장소 밖에 두거나 커밋 대상에서 뺍니다.

| 지양 | 권장 |
|---|---|
| "화장 전후로 모두 쓸 수 있을까?"에 리뷰 8건이 붙어 있으니 괜찮다고 본다 | 구체성 1점(사용 시점은 묻지만 구체 상황이 없음), 커버리지 62.5%(5/8 리뷰 적합)를 보고 질문을 좁힐 여지를 찾는다 |
| 매핑된 리뷰 수만 센다 | 리뷰마다 적합도를 매기고, 질문에 답하지 않는 리뷰 3건을 따로 본다 |
| 설정을 바꿔 돌린 두 결과를 나란히 비교한다 | 같은 모델·같은 `--max-reviews`로 전후를 돌린다 |

표의 예와 점수는 가상 데이터입니다.

## pipeline-evaluator vs writer-checker-loop

| | pipeline-evaluator | writer-checker-loop |
|---|---|---|
| 하는 일 | 이미 생성된 질문을 점수로 매긴다 | 작성 에이전트가 쓰고 검사 에이전트가 검사한다 |
| 대상 | 파이프라인 출력(`concerns.json`) | 이력서, 포트폴리오 카피, 자기소개서 같은 문서 |
| 고치는가 | 고치지 않는다. 점수와 신호만 낸다 | 사람이 게이트에서 판정하고, 작성자가 수정한다 |

pipeline-evaluator는 점수만 매기고, 무엇을 고칠지는 사람이 정합니다.

### 입력 형식

`--concerns` (Step 4 출력):

```json
{
  "concerns": {
    "제품명": [
      {
        "concernId": "c1",
        "tag": "사용 루틴/시점",
        "question": "화장 전후로 모두 쓸 수 있을까?",
        "reviewIds": ["101", "102"],
        "representativeQuote": "(선택)",
        "reviewCount": 2
      }
    ]
  }
}
```

`question`과 `reviewIds`가 핵심입니다. `concernId`, `tag`, `representativeQuote`, `reviewCount`는 없어도 돌지만 리포트에 빈 값으로 남습니다.

`--reviews` (원본 리뷰): `[{"reviewId": ..., "content": ...}]` 배열이거나 `{"results": [...]}` 객체입니다. `reviewId`는 문자열로 맞춰 비교합니다.

## 설치

```bash
cp -r pipeline-evaluator ~/.claude/skills/
```

한 프로젝트에만 쓰려면 저장소 안의 `.claude/skills/pipeline-evaluator/`에 둡니다.

사전 준비:

```bash
pip install anthropic          # 필수
pip install python-dotenv      # 선택: .env 자동 로드
export ANTHROPIC_API_KEY=...
```

`python-dotenv`가 있으면 `~/.claude/.env` 또는 `scripts/.env`에서 키를 읽습니다.

직접 돌릴 때:

```bash
python ~/.claude/skills/pipeline-evaluator/scripts/evaluate.py \
  --concerns concerns.json --reviews reviews.json \
  --output eval_report.json --max-reviews 10
```

## 범위와 한계

- 범용 평가 도구가 아닙니다. 특정 화장품 리뷰 분석 파이프라인의 Step 4 출력 형식에 맞춰 만들었습니다. 다른 파이프라인에 쓰려면 입력 형식에 데이터를 맞추거나 `evaluate.py`를 고쳐야 합니다. 루브릭(채점 기준) 예시도 피부 타입, 사용감 같은 화장품 리뷰 맥락으로 쓰여 있습니다.
- 질문당 리뷰를 최대 `--max-reviews`건(기본 10)까지만 봅니다. 커버리지는 그 표본 기준입니다.
- LLM 판정이라 실행마다 점수가 조금씩 다를 수 있습니다.
- API를 질문 수만큼 호출하므로 비용이 듭니다.
- 커버리지 경계값(40%, 90%)은 별도 검증을 거치지 않았습니다.
