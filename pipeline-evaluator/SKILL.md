# Pipeline Evaluator

## 개요

`evaluate.py` 스크립트를 실행하여 `concerns.json`의 질문 품질을 자동으로 평가한다.
평가는 Claude Haiku가 수행하며, 결과는 콘솔 요약 + JSON 리포트로 저장된다.

## 평가 지표

### 1. 구체성 지수 (Specificity) — 질문 1건당 0~2점
| 점수 | 기준 |
|------|------|
| 2점 | 특정 상황/조건/피부타입 등 디테일이 명확히 포함됨 |
| 1점 | 일반적 속성을 묻지만 디테일 부족 |
| 0점 | 지나치게 포괄적이거나 단순 찬반 |

### 2. 리뷰-질문 적합도 (Relevance) — 리뷰 1건당 1~5점
| 점수 | 기준 |
|------|------|
| 5점 | 질문에 명확하고 직접적인 답변 제공 |
| 4점 | 키워드는 없으나 맥락상 충분히 유추 가능 |
| 3점 | 같은 카테고리이나 뾰족한 답변으로는 약간 부족 |
| 2점 | 카테고리만 겹칠 뿐 질문 맥락과 무관 |
| 1점 | 전혀 상관없음 |

### 3. 커버리지 (Coverage)
- **공식:** `(적합도 3점 이상 리뷰 수) / (전체 매핑 리뷰 수) × 100`
- **< 40%:** 🔴 위험 — 질문이 지나치게 지엽적 (과적합)
- **40~70%:** 🟢 적정 — 현실적이고 실용적인 범위
- **> 90%:** 🟡 경고 — 질문이 너무 포괄적 (변별력 없음)

## 실행 방법

사용자에게 두 가지 파일 경로를 확인한 후 아래 명령어를 실행한다:

```bash
python ~/.claude/skills/pipeline-evaluator/scripts/evaluate.py \
  --concerns <concerns.json 경로> \
  --reviews  <원본 리뷰 JSON 경로> \
  --output   <결과 저장 경로 (선택)>
```

**파일 형식:**
- `--concerns`: Step 4 출력 (`concerns.json`) — `{ "concerns": { "제품명": [ { concernId, question, reviewIds, ... } ] } }`
- `--reviews`: 원본 리뷰 JSON — 배열 `[{ reviewId, content }]` 또는 `{ results: [...] }` 형식 모두 지원
- `--output`: 생략 시 자동으로 `eval_report_YYYYMMDD_HHMMSS.json` 파일로 저장

## 출력 예시

```
================================================================
📊 파이프라인 평가 리포트
================================================================

[예시 제품 A]

  [1] 사용 루틴/시점
      Q: "화장 전후로 모두 쓸 수 있을까?"
      구체성: 1점 — 일반적 사용 시점을 묻지만 구체 상황 없음
      커버리지: 62.5% 🟢 적정  (5/8 리뷰 적합)
      평균 적합도: 3.6점

================================================================
📈 전체 요약
  질문 수: 12건
  평균 구체성: 1.4 / 2
  평균 적합도: 3.2 / 5
  평균 커버리지: 58.3%
  커버리지 분포: 🔴 위험 2건 | 🟢 적정 8건 | 🟡 경고 2건
================================================================
```

## 주의사항

- 리뷰 수가 많으면 API 비용이 증가한다. 태그당 최대 10건까지만 평가한다 (기본값, `--max-reviews`로 조정 가능).
- `ANTHROPIC_API_KEY` 환경변수가 필요하다. `.env` 파일이 있으면 자동 로드된다.
- 평가 결과는 랜덤성이 있어 실행마다 약간의 차이가 있을 수 있다.
