# writer-checker-loop

숫자 하나 틀리면 안 되는 문서를 작성 에이전트 하나와 읽기 전용 검사 에이전트 여럿으로 갈라 만드는 스킬입니다.

[SKILL.md](SKILL.md) · [설치](#설치) · 에이전트 정의: [agents/](agents/)

## 구성

writer-checker-loop는 쓰는 쪽과 보는 쪽을 모델, 컨텍스트, 도구 권한까지 나누고, 단계마다 사람이 게이트에서 판정합니다. 대상은 이력서, 포트폴리오 카피, 자기소개서, 지원서 문항, 기고문입니다.

1. **원천을 카드로** — `wcl-miner`가 원문에 있는 것만 카드(원자 단위 사실 + 출처 경로)로 옮깁니다.
2. **브리프와 맞추기(선택)** — `wcl-brief-analyst`가 브리프를 요건으로 쪼개고, `wcl-matcher`가 요건 × 사실 대응표와 메시지 후보를 냅니다. 게이트 ①에서 사람이 메시지를 확정합니다.
3. **카드만 보고 쓰기** — `wcl-writer`는 원천을 보지 않습니다. 수정 모드에서는 지적된 곳만 고칩니다.
4. **두 축으로 검사** — `wcl-fact-checker`는 모든 숫자·주장을 카드까지 역추적하고, `wcl-rule-checker`는 규칙 파일 체크리스트를 전항 판정합니다. 게이트 ②에서 사람이 계속/종료/방향 수정을 고릅니다.
5. **독자 입장에서 읽기** — `wcl-reader-sim`이 대상 독자로서 판정합니다. 참고 의견이며 루프를 끝내지 않습니다. 게이트 ③에서 다시 들어갈 단위를 고릅니다.

| 에이전트 | 모델 | 도구 | 하는 일 |
|---|---|---|---|
| `wcl-miner` | sonnet | Read·Grep·Glob·Write | 원천 → 카드. 원문에 있는 것만 옮긴다 |
| `wcl-brief-analyst` (선택) | sonnet | Read·Write | 브리프 → 원자 요건. 자산과 연결하지 않는다 |
| `wcl-matcher` (선택) | opus | Read·Glob·Write | 요건 × 사실 대응표, 격차, 메시지 후보 |
| `wcl-writer` | opus | Read·Write | 카드만 보고 초안. 수정 모드에서는 지적된 곳만 고친다 |
| `wcl-fact-checker` | sonnet | Read·Grep·Glob | 모든 숫자·주장을 카드까지 역추적 |
| `wcl-rule-checker` | sonnet | Read·Grep | 규칙 파일의 체크리스트를 전항 판정 |
| `wcl-reader-sim` | opus | Read | 대상 독자로서 판정. 참고 의견 |

카드 형식, 라운드 리포트 양식, 종료 조건은 `SKILL.md`에 있습니다.

## 상황별 사용

### 이력서나 지원서 문항을 쓸 때

채용 공고라는 대상이 있고, 숫자 하나가 틀려도 신뢰를 잃는 상황입니다. 공고를 브리프로 쪼개 요건과 사실을 맞춘 뒤 게이트 ①에서 메시지를 정합니다.

중점 단계: 2. 브리프와 맞추기

### 공고 없이 기고문을 쓸 때

맞출 브리프 없이 자료에서 메시지를 골라야 하는 상황입니다. 브리프 단계를 건너뛰고 게이트 ①에서 카드를 보고 메시지를 정합니다.

중점 단계: 1. 원천을 카드로

### 같은 지적이 두 라운드를 넘겨 남을 때

문장을 다시 써도 풀리지 않는 상황입니다. 작성자에게 세 번째로 고치게 하지 않고, 자료나 템플릿 문제로 사람에게 돌려보냅니다.

중점 단계: 4. 두 축으로 검사(게이트 ②)

### 모든 단위를 다 쓰고 약한 곳을 고를 때

제목과 굵은 글씨만 훑어도 메시지가 서는지 확인하는 상황입니다.

중점 단계: 5. 독자 입장에서 읽기(게이트 ③)

### 끝낸 작업을 아티클로 정리할 때

숫자 확인보다 결정과 근거의 서사 구조가 중심인 상황입니다.

함께 쓰는 스킬: [decision-first-article](../decision-first-article/)

## 가이드라인

### 지켜야 할 것은 프롬프트가 아니라 구조로 강제합니다

규칙을 프롬프트에 적는 것만으로는 지켜지지 않습니다. 그래서 검사자에게는 `Write`·`Edit` 도구를 주지 않고, 작성자에게는 원천 대신 카드만 줍니다. 작성은 `opus`, 검사는 `sonnet`으로 나눠 자기 확인이 되지 않게 합니다.

### 검사자는 "통과"가 아니라 셈을 냅니다

`주장 14개 · 역추적 14개 · 위반 0건`처럼 셈을 내야 합니다. "문제없어 보입니다"만 말하면 실패한 실행으로 보고 다시 돌립니다.

| 지양 | 권장 |
|---|---|
| 같은 모델이 스스로 검토한다 → "문제없어 보입니다." | 읽기 전용 사실 검사자가 본다 → `주장 2개 · 역추적 2개 · 위반 2건 (non-waivable 2)` |
| "1.4배"를 그대로 둔다 | `V-DERIVED` — 카드에 없는 배수입니다. 카드 값끼리 나눠 만든 숫자입니다 |
| 범위 제한을 빼고 쓴다 | `V-SCOPE` — 카드의 범위 제한(같은 기간 캠페인 진행)이 빠졌습니다 |

표의 예는 가상의 이력서 한 줄입니다. 카드 C1은 "온보딩 완료율 30% → 42% · 같은 기간 캠페인 진행", 초안은 "온보딩을 개편해 완료율을 1.4배로 끌어올렸다"입니다. 숫자는 설명용입니다.

### 사실과 규칙은 다른 에이전트가 봅니다

한 에이전트가 둘 다 보면 한쪽 지적이 다른 쪽을 덮습니다. 사실 검사와 규칙 검사를 나누고, 한 메시지에서 둘을 함께 띄웁니다.

### 사실인지는 판정 대상이 아닙니다

메시지를 무엇으로 할지, 이 정도면 충분한지는 게이트에서 사람이 정합니다. 그러나 출처 없는 숫자, 분모 없는 비율, 카드 값끼리 계산해 만든 숫자가 하나라도 남아 있으면 사람도 "이대로 가자"를 고를 수 없습니다.

### 두 라운드를 넘긴 위반은 맨 위에 올립니다

문장을 다시 써서는 풀리지 않는 문제라는 뜻입니다. 자료가 없거나 템플릿이 틀렸으므로, 세 번째로 고치게 하지 않고 사람에게 돌려보냅니다.

### 설득은 고르는 것이지 지어내는 것이 아닙니다

심사자는 제목과 굵은 글씨만 훑습니다. 그래서 리더 시뮬레이터는 "제목만 읽어도 메시지가 서는가(5초 훑기)"를 먼저 봅니다. 어떤 참인 사실을 앞에 둘지는 편집이고, 숫자를 바꾸거나 부풀리는 것은 사실 검사가 막습니다.

## writer-checker-loop vs decision-first-article

| | writer-checker-loop | decision-first-article |
|---|---|---|
| 대상 | 이력서, 포트폴리오 카피, 자기소개서, 지원서 문항, 기고문 | 끝낸 작업을 정리한 엔지니어링 아티클 |
| 검사 방식 | 작성자와 분리된 읽기 전용 검사자, 라운드마다 사람 게이트 | 한 번 쓰고 "하면 안 되는 주장" 체크리스트로 대조 |
| 숫자 확인 | 모든 숫자를 카드까지 역추적. 파생 숫자 금지 | 넘겨받은 숫자를 원본에서 다시 센 뒤 인용 |
| 사람의 판정 | 게이트 ①②③에서 메시지, 계속 여부, 다시 들어갈 단위를 정한다 | 다시 세지 못한 숫자와 공개 여부를 사용자에게 묻는다 |

아티클의 서사 구조는 decision-first-article이 잡습니다. 틀린 숫자 하나의 비용이 추가 라운드보다 큰 문서에는 writer-checker-loop를 씁니다.

## 명세

| 항목 | 내용 |
|---|---|
| 요청 예시 | "이력서 루프 돌려줘" · "자소서 사실 검증하면서 써 줘" |
| 입력 | 원천 자료(`sources/`), 규칙 파일(`rules.md`), 선택으로 브리프(채용 공고, 공모 요강, 편집자 브리프, 채점 기준) |
| 출력 | 카드, 단위별 초안, 라운드 리포트, 라운드 기록(`rounds.md`) |
| 사전 준비 | `agents/`를 `.claude/agents/`에 복사, 규칙 파일 |
| 외부에 쓰는가 | 쓰지 않습니다. 작업 폴더 안에만 씁니다 |
| 근거 | 포트폴리오를 만들며 돌린 에이전트 구성을 일반화. 수치 측정 없음 |
| 검증 | 가상 이력서 시나리오 테스트 |

## 근거

아래 규칙은 포트폴리오를 만들며 에이전트를 직접 돌리다 생긴 실수에서 나왔습니다. 원래 정의는 채용 공고와 포트폴리오 페이지 템플릿에 묶여 있었고, 경로를 전부 호출자가 넘기게 바꾸고 공고를 "브리프"로 넓혔습니다.

| 규칙 | 근거 |
|---|---|
| 검사자에게 쓰기 도구 없음 | 프롬프트로 "수정하지 마"라고 하면 어깁니다 |
| 작성자에게 카드만 | 원천을 주면 그럴듯한 숫자를 끌어옵니다 |
| 작성 `opus`, 검사 `sonnet` | 같은 모델이 같은 맥락에서 보면 자기 확인이 됩니다 |
| 셈을 내는 보고 | "문제없어 보입니다"로 끝나는 검사를 막습니다 |
| 사실 검사와 규칙 검사 분리 | 한쪽 지적이 다른 쪽을 덮습니다 |
| `V-DERIVED`를 사실 검사 위반 유형에 추가 | 작성자가 카드의 두 값을 나눠 "약 4.7배"를 만들었습니다. 검사자 둘 중 하나는 놓쳤고 다른 하나가 잡았습니다. 원래 파생 숫자 금지는 작성자 규칙에만 있었습니다 |
| 5초 훑기 기준, 설득은 고르기 | 사용 중 피드백에서 나온 원칙입니다 |

효과를 수치로 잰 적은 아직 없습니다. 사례 하나에서 나온 설계라 정밀도 표를 붙일 단계는 아닙니다.

## 검증

가상의 이력서 작성으로 시나리오 테스트를 1라운드 했습니다. 에이전트를 실제로 띄우지 않고, 한 세션이 각 에이전트 정의의 도구와 지시 범위 안에서 차례로 역할을 맡았습니다(채굴 → 작성 → 사실 검사 → 규칙 검사 → 리더 시뮬레이션).

- **재료** — 가상 PO가 가입 온보딩을 개편한 원천 문서 3개(지표 메모, 이탈자 인터뷰, 회고). 함정 두 개를 심었습니다. "추정"이라고 표시된 매출 숫자, 명수만 있고 비율은 없는 인터뷰 결과입니다.
- **요청** — 이력서 경력 항목 5줄 작성.
- **통과** — 7개 에이전트 파일 모두 서브에이전트 frontmatter(name, description, tools, model)를 갖췄고, 검사자 셋에는 쓰기 도구가 없습니다. 추정 매출은 카드에 들어가지 않았습니다. 초안에 차이(%p)·배수·인터뷰 비율 같은 파생 숫자가 생기지 않았습니다. 카드의 범위 제한(같은 기간 캠페인 진행)이 초안 결과 줄에 반영됐습니다. 게이트 ② 리포트 양식과 종료 조건(non-waivable 0 + 사람의 종료)대로 끝까지 진행할 수 있었습니다.
- **확인하지 못한 것** — 실제 서브에이전트 실행. 모델 분리(opus/sonnet)가 실제로 놓치는 위반을 줄이는지. 2라운드 이상(반복 위반 승격, 수정 모드). `brief-analyst`·`matcher` 경로. 본인 진술(`self-reported`)을 단정형으로 쓴 문장의 위반 유형(정의가 없어 "Traced but questionable"로만 남겼습니다). 실제 사용자와 심사자의 반응.

## 설치

스킬과 에이전트를 따로 넣습니다. 스킬은 루프를 돌리는 절차이고, 에이전트는 Claude Code가 서브에이전트로 띄우는 정의 파일입니다.

```bash
cp -r writer-checker-loop ~/.claude/skills/

# 에이전트는 문서 작업을 하는 프로젝트에 넣는 걸 권한다
mkdir -p .claude/agents
cp writer-checker-loop/agents/*.md .claude/agents/
```

- 모든 프로젝트에서 쓰려면 에이전트를 `~/.claude/agents/`에 넣습니다.
- 서브에이전트는 세션 시작 때 읽히므로 새 세션을 엽니다. `/agents`로 7개가 보이는지 확인합니다.
- `wcl-` 접두어는 이미 있는 에이전트와 이름이 겹치지 않게 붙였습니다.
- 규칙 파일(`rules.md`)은 직접 써야 합니다. 작성자의 절대 규칙, 금지 문장, 구조 템플릿, 번호 붙은 체크리스트가 최소 구성입니다. 없으면 스킬이 첫 라운드 전에 사용자와 같이 만듭니다.

## 범위와 한계

- 문서 하나를 사실 근거와 규칙에 맞춰 만드는 데까지입니다. 디자인, 레이아웃, 제출은 다루지 않습니다.
- 짧은 이메일이나 한 문단짜리 글에는 과합니다. 라운드마다 에이전트 셋이 돕니다.
- 에이전트는 서브에이전트를 띄울 수 없습니다. 오케스트레이션(에이전트 호출 순서 관리)은 메인 세션이 합니다.
- 같은 모양이 지원 준비(조사 → 검토 → 비교 → 최적화 → 평가)나 파이프라인 평가(파이프라인이 작성자, 정답 카드가 근거)에도 맞습니다. `SKILL.md` 끝에 적었습니다.
- `description`은 한국어 트리거를 앞에 두고 영어 키워드(writer-checker loop, fact-check my resume 등)를 덧붙였습니다. 본문과 에이전트 정의는 영어지만, 출력 언어는 원천과 규칙 파일을 따릅니다.
