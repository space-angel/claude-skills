# ko-tech-prose

한국어 기술 문서의 문장을 규칙 단위로 진단하고, 요청할 때만 고치는 스킬입니다.

[SKILL.md](SKILL.md) · [설치](#설치) · 함께 쓰는 스킬: [plain-korean-doc](../plain-korean-doc/)

## 구성

ko-tech-prose는 검출과 판정을 나눕니다. 동봉한 스크립트가 후보를 기계적으로 찾고, 모델이 명시된 기준으로 하나씩 판정합니다.

1. **후보 뽑기** — `detect.py`가 규칙별 패턴을 문서에 겁니다.
2. **판정** — 규칙마다 적힌 통과·위반 기준으로 가르고, 위반만 남깁니다.
3. **통독** — 용어 혼용처럼 패턴으로 못 잡는 것을 문서 전체를 읽으며 확인합니다.
4. **보고** — **확실**(적용), **검토 필요**(먼저 확인), **사용자만 답할 수 있는 것** 셋으로 나눕니다.
5. **수정** — 요청할 때만 고칩니다.

검사하는 규칙은 [technical-writing.dev](https://technical-writing.dev)의 '문장 다듬기' 장에서 가져온 13개 규칙이며, 3티어로 나눴습니다.

| 티어 | 성격 | 규칙 |
|---|---|---|
| A | 패턴이 좁다. 걸리면 위반 | 이중피동, 메타 담화(`아시다시피`, `결론적으로`), 잉여 한자어(`~을 수행합니다`), 번역체 조사구(`에 있어서`), 의-연쇄 |
| B | 판정이 필요한 후보 | 겹문장, 긴 문장, 모호한 수식어, 명사화, `에 대한` 중첩, 도구가 주어인 문장 |
| C | 문서 전체를 봐야 함 | 한 개념을 여러 말로 부르기, 안 풀어쓴 약어, 표기 흔들림 |

코드블록, 인라인 코드, 링크 주소, `[[위키링크]]`, URL, 인용문, 표, YAML 프론트매터(문서 맨 위의 메타데이터)는 검사하지 않습니다.

## 모드

### 진단

"문장 봐줘", "리뷰해줘"처럼 요청하면 진단합니다. 기본 모드이며, 보고만 하고 파일은 고치지 않습니다. 모드가 애매해도 진단으로 갑니다.

### 수정

"고쳐줘", "적용해줘", `--fix`라고 하면 수정합니다. 진단을 먼저 끝내고 **확실** 항목만 적용합니다. **검토 필요** 항목은 물은 뒤 적용하고, 바꾼 내용을 표로 남깁니다.

## 상황별 사용

### 읽기 어렵다는 피드백을 받았을 때

어느 문장이 문제인지 규칙과 줄 번호로 찾아야 하는 상황입니다.

사용할 모드: 진단

### 번역체 같은 초안을 점검할 때

`에 있어서`, `~을 수행합니다`, 이중피동처럼 문장 단위 문제가 섞인 초안을 확인하는 상황입니다.

사용할 모드: 진단

### 외부에 공개하기 전일 때

README나 기술 문서를 공개하기 전에 문장을 마지막으로 점검하는 상황입니다. 작성자만 답할 수 있는 수치와 대상은 질문으로 돌려받습니다.

사용할 모드: 진단

### 진단 결과를 문서에 반영할 때

진단에서 **확실**로 나온 항목을 적용하고, **검토 필요** 항목은 물어본 뒤 적용하는 상황입니다.

사용할 모드: 수정

### 문장보다 구조와 비유가 먼저 걸릴 때

문서 배치나 비유적 어휘 때문에 독자가 막히는 상황입니다.

함께 쓰는 스킬: [plain-korean-doc](../plain-korean-doc/)

## 가이드라인

### 정규식은 후보만 찾습니다

한국어 산문에 정규식을 걸면 정밀도가 낮습니다. `C2` 모호한 수식어를 기계적으로 적용하면 열 문장 중 일곱을 망칩니다. 그래서 `C2`와 그 부류는 후보로만 내보내고, 진짜 위반과 정상 한국어를 가르는 기준을 함께 싣습니다.

### 모르는 정보는 질문으로 돌립니다

모델이 모르는 수치나 대상은 지어내지 않습니다. "일부 브라우저"처럼 작성자만 답할 수 있는 지적은 **사용자만 답할 수 있는 것**으로 보고합니다.

### '의'로 끝나는 명사는 조사로 보지 않습니다

`[가-힣]+의 [가-힣]+의` 패턴은 회의·정의·강의를 조사로 오인해 "회의 준비의 목적"을 잡았습니다. 제외 목록을 넣어 의-연쇄 정밀도를 36%에서 100%로 올렸습니다(11건 → 4건, 전부 정탐).

### 문장은 '다'+공백에서 자르지 않습니다

'다'+공백에서 자르면 "각 절마다 "에서 끊깁니다. 긴 문장이 짧은 두 토막이 되어 한 번도 검출되지 않았습니다.

### 약어는 반복될 때만 봅니다

SQL 키워드(`MAX`, `STDEV`), HTTP 메서드(`GET`, `POST`), 대문자 영어 단어(`MORE`, `OUTPUT`)를 139개 파일에서 393건 잡았습니다. 3회 이상 반복 조건과 스킵 목록을 걸어 30건으로 내렸습니다.

| 지양 | 권장 | 규칙 · 판정 |
|---|---|---|
| 설정이 완료되어야 합니다 | 설정을 완료하세요 | S2 이중피동 · 확실 |
| 삭제하는 작업을 수행합니다 | 삭제합니다 | K1 잉여 한자어 · 확실 |
| 설계에 있어서 중요한 | 설계할 때 중요한 | K2 번역체 조사구 · 확실 |
| "회의 준비의 목적"을 의-연쇄로 고친다 | '회의'는 '의'로 끝나는 명사라 그대로 둔다 | K3 의-연쇄 후보 · 통과 |
| "일부 브라우저에서"를 임의로 구체화한다 | 어느 브라우저인지 사용자에게 묻는다 | C2 모호한 수식어 · 사용자에게 질문 |

표는 가상의 초안을 진단 모드로 돌린 결과입니다.

## ko-tech-prose vs plain-korean-doc

| | ko-tech-prose | plain-korean-doc |
|---|---|---|
| 다루는 층 | 문장 | 구조, 용어, 비유, 문장 |
| 방식 | 스크립트 검출 + 규칙별 판정 | 다섯 단계를 순서대로 적용 |
| 기본 동작 | 진단만 한다. 요청할 때만 고친다 | 다듬은 문서와 변경 사항을 낸다 |
| 결과물 | 규칙·줄 번호가 달린 진단 표 | 다듬은 문서 |

문장을 규칙별로 세밀하게 진단하려면 ko-tech-prose를, 구조부터 문장까지 한 번에 다듬으려면 plain-korean-doc을 씁니다.

## 명세

| 항목 | 내용 |
|---|---|
| 요청 예시 | "문장 다듬어 줘" · "번역체 같은데 고쳐 줘" · "이 초안 손봐 줘" · "문체 점검해 줘" · "읽기 어렵다는 피드백 받았어" |
| 입력 | 마크다운 초안, README, 회고, 기획 문서 |
| 출력 | 진단 표(확실 / 검토 필요 / 사용자만 답할 수 있는 것). 수정 모드면 고친 문서와 변경 표 |
| 사전 준비 | Python 3.9 이상(표준 라이브러리만). 없어도 `SKILL.md`의 규칙표만으로 동작 |
| 외부에 쓰는가 | 쓰지 않습니다. 수정 모드에서만 대상 파일을 고칩니다 |
| 근거 | 실제 한국어 마크다운 문서 200개 코퍼스, 규칙별 표본 수작업 판정 |
| 검증 | 코퍼스 측정, 모든 규칙과 보호 구역에 위반을 심은 픽스처 |

## 근거

실제 한국어 마크다운 문서 200개에 검출기를 돌리고, 규칙별 표본을 손으로 판정했습니다. 측정 결과가 검출과 판정을 나누는 2단 구조를 정했습니다.

| 규칙 | 정밀도 | 표본 |
|---|---|---|
| tier A 전체 | 적중 13건 전수 정탐 | 13 |
| B1 겹문장 (`~며,`) | 70% | 10 |
| B3 긴 문장 (80자 초과) | 65% | 10 |
| C2 모호한 수식어 | 30% | 10 |
| T1 용어 혼용 | 약 40% | 10 |

같은 코퍼스로 조율해 총 검출을 945건에서 256건으로 줄였습니다. 문서당 중앙값은 0건이고, 200개 중 115개가 무결입니다.

## 검증

- **환경** — Python 3.9 이상, macOS.
- **재료** — 한국어 문서 200개 코퍼스, 그리고 모든 규칙과 모든 보호 구역에 위반을 심은 픽스처.
- **보완** — 측정 도중 찾은 결함은 '의'로 끝나는 명사, 문장 자르기, 약어 오탐입니다. 내용은 [가이드라인](#가이드라인)에 있습니다.
- **확인하지 못한 것** — 정밀도 수치는 코퍼스 하나를 한 사람이 판정한 값입니다. 규칙 간의 순서가 핵심이고, 정확한 퍼센트는 추정치로 봅니다.

## 설치

```bash
mkdir -p ~/.claude/skills/ko-tech-prose
cp SKILL.md detect.py ~/.claude/skills/ko-tech-prose/
```

한 프로젝트에만 쓰려면 저장소 안의 `.claude/skills/ko-tech-prose/`에 둡니다. 다음 세션부터 Claude가 알아서 꺼내 씁니다. 검출기는 Python 3.9 이상과 표준 라이브러리만 씁니다.

```bash
python3 detect.py 초안.md
python3 detect.py --tier AB 초안.md    # 문서 전역 규칙 제외
python3 detect.py --json 초안.md       # 기계 판독용
cat 초안.md | python3 detect.py -
```

스크립트 없이도 `SKILL.md`의 규칙표만으로 동작합니다. 대신 그때는 재현율이 모델이 얼마나 꼼꼼히 읽느냐에 달립니다.

팀에 맞추려면 `detect.py`의 `SYNONYM_GROUPS`, `SPELLING_PAIRS`, `ABBREV_SKIP`을 팀 용어집으로 바꿉니다. 도메인마다 다르기 때문입니다. 규칙을 추가하면 실제 문서에 돌려 적중 10건을 손으로 판정합니다. 정밀도가 50% 아래면 tier B로 내리거나 조건을 좁힙니다.

## 범위와 한계

- 문장 층만 다룹니다. 원본 가이드 3단계 중 Step 3입니다. 문서 유형 정하기와 정보 구조 설계는 의도적으로 뺐습니다.
- 한국어 전용입니다. 규칙이 한국어 문법을 담고 있고, 검출기는 한글이 절반에 못 미치는 구간을 건너뜁니다.
- 정밀도 수치는 코퍼스 하나, 판정자 한 사람에서 나왔습니다.
