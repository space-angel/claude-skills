# 팀 슬랙 메시지

## 이 스킬의 전제

**슬랙 메시지는 읽는 사람이 3초 안에 "그래서 나는 뭘 하면 되나"를 알아야 한다.**

문서처럼 배경부터 쓰면 아무도 끝까지 안 읽는다. 결론을 첫 줄에 두고, 필요한 맥락만 그 아래에 붙인다.

## 공통 규칙

- **결론이 첫 줄이다.** 무엇이 정해졌나 / 무엇이 나갔나 / 무엇을 묻나.
- **쉽고 짧게.** 맥락을 모르는 팀원(비개발자 포함)이 읽어도 알아듣게 쓴다. 개발 용어는 꼭 필요할 때만, 처음 나오면 짧게 풀어 쓴다.
- **두 줄로 욱여넣지 말고 세 줄로 나눈다.** 짧게 쓰라는 게 한 줄에 다 몰아넣으라는 뜻이 아니다. 한 줄에 한 가지만. 줄 수가 하나 늘어도 읽기 쉬운 쪽을 고른다. (8. 동료 의견에 다는 답글은 예외로 줄글로 쓴다.)
- **어조는 평서문.** "~해요/~입니다"로 담백하게. "혹시… 괜찮으시다면… 부탁드려도 될까요?" 같은 과하게 조심스러운 말투는 쓰지 않는다. 정중함은 유지하되 돌려 말하지 않는다.
- **링크를 붙인다.** 위키·이슈·PR·문서를 바꿨으면 그 링크를 메시지에 넣는다. 링크를 모르면 `<링크>` 자리표시를 남기고 사용자에게 알린다. 지어내지 않는다.
- **이모지와 굵게는 최소로.** 굵게는 메시지당 한두 곳.
- **사실만.** 대화에서 확인되지 않은 일정, 수치, 담당자를 채워 넣지 않는다. 모르면 자리표시로 남기고 묻는다.

## 유형별 템플릿

요청이 어느 유형인지 먼저 정한다. 애매하면 가장 가까운 것을 고르고 따로 묻지 않는다.

### 1. 결정 사항 공지

```
<무엇을> <어떻게> 하기로 했어요.

• 이유: <한 줄>
• 바뀌는 것: <누가 무엇을 다르게 하면 되나>
• 기록: <위키/이슈 링크>
```

### 2. 배포 공유

```
<무엇>을 배포했어요. <사용자가 체감하는 변화 한 줄>

• 바뀐 점: <1~3개>
• 확인 방법: <어디서 보면 되나>
• 링크: <PR/릴리스/화면>
```

배포 범위를 모르면 "바뀐 점"을 비워두고 묻는다. 커밋 목록을 그대로 옮기지 않는다.

### 3. 팀원에게 묻는 질문

```
OO님, <질문 한 줄>

지금: <내가 확인한 현재 상태>
필요한 이유: <이걸 알아야 뭘 할 수 있나>
```

질문은 하나만. 예/아니오나 짧은 답으로 끝날 수 있게 묻는다.

### 4. PO에게 결정 요청

```
<무엇>을 정해야 해요. <언제까지/무엇이 막혀 있나>

지금: <현재 상태 — 코드/화면이 지금 어떻게 동작하나>
선택지:
  A. <안> — <결과/비용>
  B. <안> — <결과/비용>
제안: <있으면 하나, 이유 한 줄>
정해지면: <이 결정으로 무엇이 진행되나>
```

채널에 올리는 거면 첫 줄 앞에 `OO님,`을 붙여 PO를 부른다. 제안이 없으면 `제안:` 줄은 지운다. 결정이 여러 개면 번호를 붙여 하나씩 나눈다. 각 항목에 **현재 상태, 선택지, 무엇이 결정되는지**가 다 있어야 한다. PO가 코드를 몰라도 고를 수 있게 선택지는 결과로 쓴다("값만 비교" 대신 "제목이 바뀌어도 알림이 안 가요").

### 5. 위키·이슈 변경 공지

```
<무엇>을 <위키/이슈>에 반영했어요.

• 바뀐 것: <이전 → 지금>
• 영향: <누가 확인해야 하나>
• 링크: <링크>
```

### 6. 데일리 리포트

```
<날짜> 작업 정리

• 끝낸 것: <결과 중심 1~3개>
• 진행 중: <1~2개>
• 막힌 것 / 도움 필요: <없으면 "없음">
```

개조식으로 컴팩트하게. 비개발자도 읽는 채널이면 작업 이름 대신 결과를 쓴다.

### 7. 설문

```
<무엇>에 대해 의견 받아요. <마감>까지 이모지로 답해주세요.

:one: <선택지>
:two: <선택지>
:three: 기타 — 스레드에 남겨주세요
```

선택지는 서로 겹치지 않게. 선택지 수는 4개 이하.

### 8. 동료 의견에 다는 답글

**이 유형은 형식이 다르다.**

- **이름을 부르지 않는다.** "OO님 말씀처럼…"으로 시작하지 않는다. 스레드 답글이라 누구에게 하는 말인지 이미 보인다.
- **불릿으로 나누지 않는다.** 줄글로 쓴다. 의견을 항목으로 쪼개면 보고서처럼 읽힌다.
- **내 의견을 솔직하게.** 동의하면 왜 동의하는지, 다르면 어디가 다른지를 바로 쓴다. 칭찬으로 감싸고 시작하지 않는다.

```
<내 입장 한 문장>. <이유 한두 문장>. <다르게 본 지점이나 덧붙이고 싶은 것 한 문장>.
```

## 출력

1. **메시지를 코드블록에 담아 준다.** 바로 복사해 붙여넣을 수 있게. 코드블록 밖에 설명을 섞지 않는다.
2. 자리표시(`<링크>`, `OO님`)가 남았으면 코드블록 아래에 한 줄로 알린다.
3. 길이 차이가 큰 두 안이 다 그럴듯하면 짧은 안과 긴 안을 둘 다 준다. 그 외에는 하나만.

슬랙 서식은 마크다운과 다르다. 굵게는 `*별표 하나*`다. `**`는 그대로 보인다. 제목(`#`)과 표는 안 된다.

## 보내지 않는다

메시지를 쓰는 것까지가 이 스킬이다. **보내는 건 사용자의 일이다.** 슬랙 커넥터가 연결돼 있어도 사용자가 "보내줘", "올려줘"라고 명시하기 전에는 보내지 않는다. 명시했더라도 채널과 최종 문구를 한 번 보여주고 확인받은 뒤 보낸다.
